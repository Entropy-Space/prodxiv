# Paper references

Use this component for Background, Related Work, inline citations, and the
References section.

1. Begin with the product problem and identify the external facts needed to
   explain its domain, affected users, constraints, and existing approaches.
2. Identify specific related products, websites, repositories,
   documentation, standards, or papers.
3. Prefer official sites, documentation, and source repositories for claims
   about a product's behavior.
4. Use independent sources when a comparison requires an outside perspective.
5. Explain how each work approaches the same problem and whether it is an
   influence, dependency, alternative, or predecessor instead of listing names.
6. Place a descriptive Markdown link near each externally verifiable claim.
7. Include complete, publicly inspectable links in References.
8. Mark unsupported comparisons for author review.

Never disclose private repository text, paths, or implementation details in a
search query or public citation.
