# Project architecture

Use this component to explain implementation boundaries from repository
evidence.

1. Identify runtime entry points, major modules, persistence, external
   services, and build or deployment boundaries.
2. Trace important data and control flows through inspectable source.
3. Distinguish implemented architecture from planned architecture.
4. Name dependencies only when they materially explain the product.
5. Prefer a compact workflow or boundary diagram when it clarifies three or
   more relationships.
6. Cite repository paths privately during review; do not publish local paths as
   public references.

Ask the author why boundaries were chosen instead of inventing design intent.
